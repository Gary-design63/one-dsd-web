# A walk through the Program

What a Disability Services Division staff member sees, in the order they see it.

## How these were taken

The Program was built from this branch and served on this machine, and the pages were photographed there. The site itself could not be reached from the machine that took them.

1440 points wide at double resolution; long pages are shown from the top of the page.

Two things do not appear in a local run and are not defects of the Program: files attached to a resource, which need the program database, and live checking of current public sources, which needs the research service. Neither was fabricated and nothing in any image was altered.

## One screenshot that was asked for and is not here

**The consultant portal request-submission workflow** (`/support/request`, `/support/track`).

These pages do not show a submission form. Checked on a local run of this branch on 2026-09-19: /support/track reads “Checking a request is not available right now”, and /support/request routes to “Direct consultation is for DSD work” rather than to intake. Intake is deliberately fail-closed in lib/intelligence/consult/availability.ts: it requires a PostgreSQL store, a runtime database URL, a tracking secret, a rate-limit secret, an approved and matching activation-evidence bundle, an approved policy version, an approved retention period, and seven separate readiness switches for correction, deletion, backup, restore, recovery, incident and delivery processes. Every one of those switches defaults to off in config/environment-contract.json, and the approved retention period in particular has not been set. The production environment's variables cannot be read from here, so this describes the code and the defaults, not an inspection of production.

A screenshot of this workflow would show a closed page to a Division Director, which would undercut the package rather than support it.

**Decision.** Omitted. Gary chose this on 2026-09-19: the Support screenshot carries the point, because “Find the right person” works today and names the office, the role, and what that office can decide. The memorandum is strongest where every screenshot is something a staff member can do today.
