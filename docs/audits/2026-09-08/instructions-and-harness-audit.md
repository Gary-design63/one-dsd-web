# Instructions and harness audit

September 8, 2026 · One DHS People, Access and Culture Program

**Disposition: proposals only. No application code, active instructions, configuration, permissions, database, deployment settings, or installed skills were changed for this audit.**

## Finding

Keep the owner's canonical requirements. Simplify how they are located and applied, separate current direction from historical records, and make verification prove the requested outcome. The evidence supports concrete workflow friction and documentation ambiguity. It does not establish that instruction volume made the model less capable or caused the image failure.

The image incident was an implementation and judgment failure: the agent equated a desired dimensional appearance with a particular rendering technique, and later proved stillness without proving visual fidelity. The working agreement already prohibited unexplained material changes and repeated approval requests. Those instructions were useful and were not followed adequately. More unrestricted access would not have fixed that mistake.

## Evidence and scope

Inspected the active repository's AGENTS.md; owner directive, working agreement, staff voice standard; execution authority, autonomy, architecture, decisions, handoff and implementation-plan documents; deployment/test configuration and scripts; and the runtime policy, tool enforcement and relevant agent definitions. Checked selected local Codex configuration fields without exporting secrets. Used the visible conversation and actual deployment records for the image incident.

The global `C:/Users/garyb/.codex/AGENTS.md` exists but is empty. The repository AGENTS.md is 4,319 bytes and approximately 580 whitespace-delimited words. Ten project guidance documents total approximately 17,648 words, but that is a disk inventory, **not proof they are all automatically injected into every turn**. OpenAI documents layered AGENTS discovery; arbitrary linked documents do not become the same thing as the automatically discovered AGENTS chain. No instruction-limit overflow was established. See [official AGENTS guidance](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

This is an audit of the accessible project/development harness and its relevant program-agent controls, not a certification of every product workflow, every historical PRD paragraph, every installed skill, hidden platform internals, or all live agent permissions. Original source packages were not rewritten. The effective live program policy was not queried or changed; code defaults are not treated as live settings. There was no controlled before/after model experiment, so performance gains below are proposed, not measured.

## Keep these canonical commitments

Preserve DIGITAL MING, the owner's final product decisions, the Chief of Staff's coordinating role, the measurable 90–95% agent-driven ambition, broad ASK capability, durable answer/work receipts, already approved owner-curated content, warm professional staff language, original sources, One DHS/One DSD scope, the $200 monthly external-research limit, and the owner's exclusion of Sonar. Keep accessibility, truthful failure reporting, source attribution, applicable scoped access and owner stop controls. Keep development conversations out of staff-facing copy.

Separate three meanings of approval: the owner's content approval, authorization for the current task/deployment, and managed execution controls. Approval in one category does not imply a missing approval in another. Existing authorization should not be requested again.

## Adoption order and a small evaluation

1. Correct location/authority references and create the current index (IDs 1–3).
2. Adopt the shorter entrypoint and outcome-based verification wording (IDs 4–5).
3. Optimize the release workflow with enforced exact-commit verification (IDs 6–7).
4. Align the app workspace and reconcile program-agent capabilities using real tasks (IDs 8–9); improve handoffs and communication throughout (ID 10).

Before adopting a lighter harness broadly, compare the current and proposed guidance on the same bounded examples: reproduce an approved image, update one published description without changing other copy, resume a deployment from a handoff, answer a resource question with a matching citation, and complete one authorized specialist task. Keep the model, inputs and acceptance criteria constant. Measure correctness, unnecessary approval questions, rework, elapsed time and available usage—not just instruction length. Start with offline/local examples; no duplicate live side effects are necessary.

No proposed instruction may silently weaken a canonical requirement. No lower-priority project file can override managed platform controls. Review the companion draft entrypoint before adoption.
